`720DDF9BCC2171C0111E0BEEA61E989B73793219FEEEF4B9EF5CECB9C83F31B4`.

`444D8EE33ED78BA4A427810E35A62731F4D845CBAC7343B37B16A5C20F3C34A4`.
Checks use D3D12, Ordon `F_SP103,0,27,0`, a 960×720 world target and isolated user

replacement textures are disabled to isolate rate ownership. Auto-save is off.

The [temporary SDK fixture](driver.cpp) requests native frame blending at alpha
160 with an identity blur matrix. It uses native JUT pad replay for a short
forward movement route that triggers the real conversation event. It then ends
its request program and restores its borrowed rate/matrix and replay pointer.
This is a synthetic native request, not a claim about the game's default blur
strength in this scene. The fixture binary does not ship. [Build definition](driver-CMakeLists.txt),
[launch script](launch-native.ps1), driver hashes, logs and raw rows are retained.

## Automated proof

The Release build and [three focused tests](focused-tests.log) pass: motion
clarity, profile round trips and package layout. The portable motion test covers
all 256 native rates against all 101 percentages, bounds, monotonicity, nearest
rounding, clamped percentages, zero and unchanged endpoints. It also exercises
all 64 safety-gate combinations and individual event/demo/pause/fade bypasses.

Ownership cases cover restoration of an owned zero, repeated application without
compounding, fresh native requests, skipped-scope recovery, cancellation at 100%
retention and preservation of detectable intervening writes. Product masks now
accept 255; an earlier mask of 127 leaves motion clarity off. Scene mask behavior
and numeric tuning remain unchanged.

The partial-retention package also reloads through native UI and remains active;

The screenshot shows the native conversation context, not a matched blur-quality

## Retained limits and diagnostic correction

An initial local package (`1FB18CA554ADC519831E88C4BADE406207B0FD0D9964045DD2F61342E63385FF`)
passes the original three native programs retained in `native-on`, `native-off`
and `native-half`. Inline review then identifies that the demo-camera getter
requires a non-null demo manager. The final package skips disabled/missing-player
and full-retention work before querying it and treats a missing manager as a
blocked context. The final three programs repeat the audit after this repair.
The control screenshots are from the initial package's identical UI.

The initial analysis included HUD callbacks from startup before the fixture had
requested blur. Those rows legitimately contain alpha zero and no enable flag;
they are not restoration failures. The final assertion associates HUD rows with
ticks containing a fixture scene-begin request. Raw startup rows remain in each
CSV, and the 78 excluded startup rows in each final run are explicit in the summary.

The empty card reports `Failed to open file: gczelda2`. After all mods unload,
the host reports aborted buffer mappings and `Device lost: Device was destroyed.`
These known teardown warnings remain in the logs; the processes still exit zero.
