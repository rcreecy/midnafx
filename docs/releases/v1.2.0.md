MidnaFX 1.2.0 adds experimental pre-HUD anti-aliasing, enabled by default for new configurations.

The Basic anti-aliasing toggle operates independently of grading and saved looks.
Existing saved AA-off values remain off. The conservative five-tap FXAA-style
filter preserves source alpha and avoids filtering low-contrast regions.
Detail enhancement shares its source samples and does not sharpen edges selected
for AA. The ordinary and enhanced-water paths use the same repaired behavior.

This release also fixes saved grading, detail, and Twilight adjustments leaking
into independently enabled AA/water draws while Enable grading is off.

Windows verification passes all 16 tests, including 25 offscreen D3D12 pixel
cases on Intel UHD Graphics 630, shader compilation, and package validation.
Earlier prototype smoke runs cover scene rendering, resize, DOF, and shutdown;
instrumented logs cover toggles, reload, transitions, and camera movement.
Those earlier runs do not visually qualify the final repaired package.

Known limits: the filter is an FXAA-style approximation, not full reference FXAA
or temporal AA. Fine-detail retention, temporal shimmering, enhanced-water
boundaries, final-package live visual quality, and GPU performance remain
unqualified. Intel Mac packages are CI-built; live game/Metal validation remains
pending. Disable Anti-aliasing (experimental) in Basic settings if unwanted
softening occurs. Default-on follows the explicit product decision despite these
remaining visual checks.

This release ships the validated Windows package only. The Intel Mac build compiled, but its AA pixel test failed on the hosted Apple Paravirtual Metal device (including basic pixel identity). The cause is unresolved; the Mac asset is withheld. This is not a claim that physical Intel Macs fail. See the [CI run](https://github.com/rcreecy/midnafx/actions/runs/37865908505).
